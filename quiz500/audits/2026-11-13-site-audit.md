## 범위와 한계

이 조사는 기존 사이트 코드와 문제·해설을 변경하지 않았다. 실제 공개 사이트를 원격 Chrome의 데스크톱 화면으로 열어 표본 동작을 살폈고, GitHub 공개 소스 및 문제 배열을 자동 집계했다. 화면상 문제 수와 계산 결과는 일치했으나 배포된 모든 파일이 기준 커밋과 바이트 단위로 동일한지는 검증하지 않았다.

모바일 360~390px, 태블릿 768px, 별도의 1440px 뷰포트 시험 및 실기기 시험은 수행하지 못했다. 따라서 반응형 정상 동작 여부를 결론 내리지 않는다. 3D는 이 원격 브라우저의 WebGL 컨텍스트 생성 실패로 장면·움직임을 검증하지 못했다. 해당 브라우저의 렌더러가 비활성화되었다는 로그가 있어, 이 결과만으로 일반 사용자 기기에서도 실패한다고 판단할 수 없다. 전체 링크, 모든 문제, 모든 기관 자료, 정답·해설, 출처 권리, 성능과 접근성을 전수 검증하지 않았다. 본문에 없는 사항은 미확인이다.

## 1. 주요 발견 — 우선 조치

### P0: 통신공학 필터와 실제 표시 문제가 달라지는 오류

- 재현: 통신공학 학습 홈에서 문제 유형을 “2024년도 지방공무원 9급 채용 기출”, 출제 순서를 “PDF 페이지순”으로 선택하고 학습 시작.
- 관찰: 첫 문제 상단에 “2025년도 지방공무원 9급 채용 기출”과 ID `ADD-comm-the-Q01-0`이 표시됐다.
- 코드 분석: 통신공학 BANK의 40개 ID가 반복되고, 이들 각 ID에는 서로 다른 문제 본문이 존재한다. 문제 선택에 사용하는 코드가 `BANK.find(q => q.id === ...)`로 첫 번째 일치 항목을 반환하므로, 선택한 연도의 항목 대신 같은 ID의 앞선 항목이 나타나는 것으로 설명된다.
- 범위: 40개 중복 ID에 총 251개 레코드가 연결되어 있고, 고유 ID 기준 중복분은 211개다. 이는 211개의 문제가 내용상 복제되었다는 뜻이 아니다. 서로 다른 문항이 같은 ID를 사용하며, 선별된 조건에서 실제 표시 및 즐겨찾기·오답·학습 이력의 혼선이 발생할 위험이 있다. 재현은 위 한 조건에서 확인했다.
- 권장: 원본 출처와 회차·번호를 포함하는 안정적 ID를 설계하고 기존 저장 기록의 매핑 가능성을 점검한다. 기존 ID 하나가 여러 문제를 가리키므로 과거 기록을 정확히 어느 문제에 배정할지는 자동으로 확정할 수 없다. 임의로 덮어쓰지 말고 백업·이관 및 미해결 항목을 설계해야 한다.

### P0: 수식·그림을 읽기 어려운 통신공학 문제

- 실제 표본 `NG2019-COMM-Q15`: AM 변조기 문제에서 본문과 선택지 수식이 네모 글자로 보였고, 그림을 요구하는 문장과 기호가 정상적인 그림 없이 표시되었다. 선택 후 “채점 보류 · 원문 대조 필요” 표시를 확인했다.
- 자동 집계: 본문 또는 선택지에 유니코드 사설 영역(U+E000~U+F8FF) 문자를 포함한 레코드 287개. 이는 표시 오류 위험의 대리 지표이며 모든 문항의 실제 렌더링 불량을 확정한 수치는 아니다. 본문에 “다음 그림/회로/표” 표현이 있는 레코드 19개는 이미지 필요성 확인 대상일 뿐, 모두 누락되었다는 뜻은 아니다.
- 통신공학 레코드 중 본문이 비어 있고 선택지 배열도 비어 있는 항목이 14개 존재한다. 이 14개는 코드 데이터 자동 점검 결과이며 화면에서 각각 확인하지 않았다.
- 권장: 원문과 권리를 확인하여 수식·그림을 복원하고 정상 제공 전에는 명확히 안내하거나 제공을 보류한다. 추측으로 내용을 만들지 않는다.

### P1: 채점 보류 문항이 누적 정답률 분모에 포함될 가능성

- 실제 원격 브라우저에서 채점 보류 문항 2개를 선택한 뒤 새로고침하자 홈에 풀이 횟수 2회, 누적 정답률 0%, 복습 오답 0문항이 표시됐다.
- 코드상 진행 정보의 `seen`은 채점 보류에도 증가하고 홈 정답률은 `correct/seen`으로 계산된다. 반면 학습 종료 결과는 `gradedCount`로 계산한다.
- 따라서 채점 보류 문항만 푼 경우에도 누적 정답률이 0%처럼 표현되어 학습자를 혼란스럽게 할 수 있다. 서로 다른 이력 상태에서의 전수 시험은 하지 않았다.

### P1: 표시 정보의 불일치

- 통신공학 실제 홈의 주 제목·전체 수는 1,762이나 상단 브랜드에는 “통신공학 1503”이 표시된다.
- 무선공학 실제 홈의 주 제목·전체 수는 2,156이나 상단 브랜드에는 “무선공학 1074”가 표시된다. 저장소의 무선공학 README도 1,074문항이라고 적혀 있다.
- 면접 목록에는 서울교통공사 LTE-R 중심 기술질문 22개라고 안내하지만, 서울교통공사 페이지의 펼친 메뉴에는 “LTE-R 40개”라고 표시된다. 두 수치의 범위가 같은지, 실제 문항 수가 각각 정확한지는 아직 세지 않았다.
- 홈페이지에는 과거 업데이트 당시의 문항 수가 여럿 현재 수치 아래에 함께 노출된다. 과거 이력 자체는 유용하지만 현재 값과 구분을 강화하는 것이 좋다.

## 2. 문항 집계 방법과 결과

통신공학은 실제 페이지의 인라인 `const BANK` 배열을 JSON으로 파싱했다. 무선공학은 저장소의 인라인 기본 BANK, 같은 파일 내 4개의 추가 배열, 외부로 불러오는 3개 추가 JS 배열을 모두 파싱해 합산했다. 다른 CSV/JSON 백업 및 별도 문제은행은 같은 문제를 중복 집계할 수 있으므로 본 앱의 실행 배열에 중복 합산하지 않았다. 동작 시 추가적인 런타임 변경 여부는 관련 push 코드를 확인한 범위에 한한다.

| 구분 | 실행 배열 레코드 수 | 홈페이지 표시 수 | 고유 ID 수 | 정답 인덱스 없음 또는 범위 밖 | 설명 필드 빈 값 |
|---|---:|---:|---:|---:|---:|
| 통신공학 | 1,762 | 1,762 | 1,551 | 338 | 0 |
| 무선공학 | 2,156 | 2,156 | 2,156 | 0 | 0 |
| 합계 | 3,918 | 3,918 | 과목별 별도 ID | 338 | 0 |

통신공학의 338개는 모두 `answer`가 null 또는 미설정인 항목이고 범위 밖 정수는 없었다. 이는 의도적으로 채점 보류한 항목을 포함하며 전부 오류라는 뜻이 아니다. 설명 필드가 있다는 사실은 해설이 충분하거나 정확하다는 검증이 아니다. 등록 레코드 수는 고유하게 정상 풀이 가능한 문항 수와 다르다.

무선공학 구성: 기본 1,074 + HTML 내 추가 45·52·57·41 + 외부 A 434 + 외부 B 433 + reviewed-first4 20 = 2,156. JS 파일명에 reviewed가 들어가더라도 원문·정답·해설을 이번 조사에서 검증 완료했다는 뜻은 아니다.

자동으로 문제 본문과 선택지 배열이 정확히 동일한 그룹을 비교했을 때, 통신공학에서는 본문과 선택지가 비어 있는 14개가 1개 그룹으로 묶였다. 무선공학에서는 106개 그룹, 232개 레코드가 일치했다. 이 결과는 출처·시험 회차·표현 차이·정답 등을 비교하지 않은 후보이며 중복 삭제 대상으로 확정하지 않는다.

## 4. 기존 학습 기록

코드 확인 결과 두 앱은 브라우저 localStorage를 각각 사용한다.

- 통신공학: 현재 `comms500_prefs_v2`, 과거 `comms500_stats_v1`
- 무선공학: 현재 `wireless500_prefs_v2`, 과거 `wireless500_stats_v1`
- 현재 저장 내용은 `version: 3`, 문제 ID별 progress, bookmarks, history, theme이다.
- 통신공학에서 채점 보류 문제 풀이 후 새로고침 시 누적 풀이 횟수 2회가 유지됨을 관찰했다. 기록 전체의 장기 보존, 내보내기, 기기 간 동기화는 실험하지 않았다.
- 브라우저별·기기별 저장이므로 사이트 데이터 삭제나 다른 기기 사용 시 해당 기록이 보이지 않을 수 있다.
- 현재 데이터는 ID에 의존한다. 중복 ID 수정과 저장 키 변경은 기존 이력에 영향을 줄 수 있으므로 이관 테스트와 사용자별 백업을 동반해야 한다. 이번 조사에서는 실제 이용자의 데이터를 읽거나 변경하지 않았다. 테스트는 원격 브라우저에서 수행했다.

## 6. 개선 우선순위와 후속 범위

1. 최우선 신뢰성: 통신공학 중복 ID와 잘못된 문제 호출, 빈 문제·선택지, 깨지는 수식·그림, 채점 보류 통계. 원문 확인·기록 이관 계획을 먼저 수립.
2. 2번째 요청 범위: 홈페이지 첫 화면, 기관별 진입, 학습 경로, 업데이트 요약, 모바일 버튼·가독성. 기존 데이터와 URL을 유지. 위 문제은행 결함은 별도 문제로 기록하며 이 단계에서 무단으로 문제·해설을 변경하지 않는다.
3. 3번째 요청 범위: 문항 출처·상태·신고, 자동 점검과 원문 대조 분리. 중복 ID 해결은 학습 기록 이관과 문제 데이터 보존을 포함하는 별도 설계를 선행한다.
4. 4번째 요청 범위: 기관 자료의 시점·출처·예상 질문 구분 및 시뮬레이션과 면접/문제 연결. WebGL 가능한 환경 및 모바일에서 확인한다.
5. 별도 추후 검토: 저작권, 개인정보, 광고 정책, 상업적 운영에 적합한 호스팅. 현재 단계에서 승인이나 수익을 보장할 수 없다.

## 7. 사이트 복사 방지의 현실적인 범위

현재 저장소가 공개되어 있고 웹 브라우저에 전달되는 HTML·JavaScript·문제 데이터는 이용자가 열람·저장할 수 있다. 마우스 오른쪽 클릭 차단이나 코드 난독화는 복사를 완전히 막지 못한다. 비공개 저장소 전환이나 호스팅 이전은 공개 사이트의 운영·배포에 영향을 미칠 수 있으므로 이번 조사에서는 수행하지 않았다. 브랜드 표시, 저작권 및 이용 조건 표기, 필요한 권리 확인, 서버 측 제공 등은 무단 복제를 어렵게 하거나 대응을 돕는 선택지이지만 어느 것도 공개된 화면의 완전한 복사 방지를 보장하지 않는다. 실제 적용은 범위와 비용·운영 방식 검토 후 진행한다.
